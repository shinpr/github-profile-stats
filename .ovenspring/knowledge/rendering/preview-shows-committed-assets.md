# The preview and the README show the committed SVGs in assets/, and no local command regenerates them

`npm run preview` (`scripts/preview.mjs`) serves the files in `assets/` as they are committed, each inside an `<img>`, and the README embeds the same files. The code that draws cards does live here: the action (`src/action.mjs` → `generateProfileStats` → `renderArtifacts` in `src/generate.mjs`) renders every format from `src/render`. But no npm script or workflow in this repository runs it to rewrite `assets/`; the README says they "are generated for `shinpr` by the production pipeline", and they were last updated at `5282a47` and `d4fc303`. So a change to what a card draws does not appear in the preview, in the README, or in the owner's preview of a rendering hold unless those SVGs are rendered again from the changed code. The sample data in them (language shares 47/39/8/5/1) also does not reach edge values such as `<1%` or `>99%`.

Applies when a step needs to see, or show the owner, how a changed card looks. To see it, render the card through `src/render` (or `renderArtifacts`) with data that hits the changed case; the tests under `test/render/` and `test/integration/generate.test.mjs` build such data. Stops applying when the repository gains a local command that regenerates `assets/`.
